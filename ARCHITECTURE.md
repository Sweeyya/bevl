# Toros: Architecture

Read this before editing any package. It defines the two contracts that all packages must agree on.

---

## 1. Package map

```
brand kit / DESIGN.md
        │
        ▼
  @toros/tokens ──────────────────────────────────────────► Theme
        │                                                        │
        ▼                                                        ▼
  @toros/core ◄──── @toros/a11y          @toros/effects ◄─┘
  (3D runtime)        (HTML layer)           (glass, shaders)
        │                   │
        └──────────┬─────────┘
                   ▼
            Built 3D site
                   │
        ┌──────────▼──────────┐
        │   @toros/check    │  ◄── @toros/optimizer
        │  (browser + rules)  │
        └──────────┬──────────┘
                   ▼
             report.json  (score 0-100)
                   │
        ┌──────────▼──────────┐
        │    @toros/mcp     │
        │    @toros/cli     │
        └─────────────────────┘
```

## 2. Contract A: `toros.json`

Every project generated by Toros has a `toros.json` at its root.
This is the shared config that `core`, `check`, and `cli` all read.

```ts
// packages/core/src/contract.ts

export interface TorosConfig {
  /** Project name, used in reports */
  name: string;
  /** Path to the brand/token file (DESIGN.md or design-token JSON) */
  brand?: string;
  /** Ordered list of sections */
  sections: SectionConfig[];
  /** How progress (0-1) drives the scene. Default: fly forward, one beat per section.
   *  See packages/core/src/choreography/types.ts and docs/adr/003-scroll-choreography.md */
  choreography?: Choreography;
  /** Where ?toros-test is honored: "localhost" (default), "always", "never" */
  testMode?: "localhost" | "always" | "never";
  /** Performance budgets. Defaults come from toros.budgets.json */
  budgets?: Partial<Budgets>;
  /** Viewports to test. Defaults: desktop + phone */
  viewports?: ViewportConfig[];
}

export interface SectionConfig {
  id: string;
  title: string;
  /** Scroll anchor (0-1). Computed automatically if omitted. */
  anchor?: number;
}

export interface Budgets {
  trianglesDesktop: number;
  trianglesPhone: number;
  drawCallsDesktop: number;
  drawCallsPhone: number;
  textureMbDesktop: number;
  textureMbPhone: number;
  modelMb: number;
  jsKb: number;
  readyMsDesktop: number;
  readyMsPhone: number;
  maxStepMeters: number;
  maxTurnPerStepDeg: number;
}

export interface ViewportConfig {
  name: string;
  width: number;
  height: number;
  deviceScaleFactor: number;
  isMobile: boolean;
  hasTouch: boolean;
}
```

If this contract changes, update `ARCHITECTURE.md` first, then update every package that reads it.

## 3. Contract B: `window.__toros` (test mode only)

When a Toros site loads with `?toros-test` in the URL, `@toros/core`
sets `window.__toros`. The checker reads this bridge. It never writes to it
except through real browser input (scroll, click, keyboard).

```ts
// packages/core/src/contract.ts (continued)

export interface TorosBridge {
  /** Resolves when scene, assets and fonts are loaded */
  ready: Promise<void>;
  /** Advance time by ms. Returns the new time and frame number. */
  step(ms: number): { time: number; frame: number };
  /** Every section with its scroll anchor and camera pose */
  sections(): SectionState[];
  /** Current camera state */
  camera(): CameraState;
  /** The validated choreography in effect: beats, snap settings and motion allowances (read-only) */
  choreography(): Choreography;
  /** Live prefers-reduced-motion preference of the page */
  motion(): { reducedMotion: boolean };
  /** Current scroll progress 0-1 */
  scroll(): number;
  /** Scene stats (triangles, draw calls, texture MB, etc.) */
  stats(): SceneStats;
  /** Every distinct material in the scene: name and hex colors (color, plus emissive when not black) */
  materials(): MaterialState[];
  /** Brand tokens the site was given (`<TorosSite brand={...}>`), or null. Brand rules are skipped on null. */
  brand(): BrandTokens | null;
  /** Any 3D text meshes (should have <= 40 chars each). An object counts as a text mesh when
   *  `object.userData.torosText` is a string, whatever component renders it. */
  textMeshes(): TextMeshState[];
  /** Mascot state if present */
  mascot(): MascotState | null;
  /** Ordered event log */
  events(): TorosEvent[];
}

export interface SectionState {
  id: string;
  index: number;
  anchor: number;
  cameraPose: Pose;
  domId: string;
}

export interface CameraState {
  position: Vec3;
  quaternion: Quat;
  up: Vec3;
  fov: number;
  sectionId: string | null;
}

export interface SceneStats {
  triangles: number;
  drawCalls: number;
  geometries: number;
  textures: number;
  textureMbEstimate: number;
}

export interface Pose {
  position: Vec3;
  quaternion: Quat;
}
export interface Vec3 {
  x: number;
  y: number;
  z: number;
}
export interface Quat {
  x: number;
  y: number;
  z: number;
  w: number;
}

export type MaterialState = { name: string; colors: string[] };
export type TextMeshState = { text: string; charCount: number };
export type MascotState = { visible: boolean; screenBox: Box2; state: string };
export type Box2 = { x: number; y: number; width: number; height: number };
export type TorosEvent =
  | { type: "section-entered"; sectionId: string; time: number }
  | { type: "nav-clicked"; target: string; time: number }
  | { type: "glide-start"; from: string; to: string; time: number }
  | { type: "glide-end"; sectionId: string; time: number }
  | { type: "error"; message: string; time: number };
```

If this contract changes, update `ARCHITECTURE.md` first.

## 4. Data flow: brand kit to finished site

1. User gives Claude a brand kit (DESIGN.md or token JSON).
2. `@toros/tokens` reads the kit and returns a `Theme` (colors, fonts, material preset, light rig).
3. `@toros/core` renders the site using that `Theme`.
4. `@toros/effects` applies glass and shader background, using `Theme` for colors.
5. `@toros/a11y` builds the HTML layer on top, also using `Theme` for fonts.
6. The agent calls `toros check`. `@toros/check` opens the site in Chromium, waits for `window.__toros.ready`, then runs every rule.
7. The report comes back as JSON. The agent reads the `findings` array and fixes each one.
8. The agent loops until `score >= 90` and no errors remain.

## 5. Test mode details

See `docs/adr/002-test-mode.md` and `TESTING.md §2`.

The key rule: **the checker never calls `step()` to advance time**. It uses real browser input only (wheel events, touch, clicks, keyboard). `step()` is only used in unit tests that test the camera math directly.

---

## 5b. HTML content layer

Section text is real HTML. `<Section id title html={...}>` registers its html with `TorosSite`, which renders it outside the canvas in a fixed, pointer-events-none layer: one `<main id="main-content">` with one `<section id="section-<id>">` per section. Visibility follows progress (opacity and transform written from the frame loop); all text stays in the DOM and Tab follows section order. See `docs/adr/004-html-content-layer.md`.

---

## 6. Package dependency rules

- `core` has no `@toros/*` dependencies.
- `tokens` has no `@toros/*` dependencies.
- `a11y`, `effects`, `mascot` depend on `core` only.
- `check` has no `@toros/*` dependencies (it talks to the site through the browser).
- `optimizer` has no `@toros/*` dependencies.
- `mcp` and `cli` may depend on `check`, `core`, `tokens`, and `optimizer` (core only for recipes, see `docs/adr/009-recipe-apply.md`).
- No circular dependencies.
